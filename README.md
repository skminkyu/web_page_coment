# 상세페이지 주석 검토 (web_page_coment)

제품별·차수별로 상세페이지(이미지·HTML·소스코드/텍스트)를 올리고, 수정이 필요한 곳에 **박스** 또는 **핀**을 지정해 코멘트를 다는 검토 도구입니다.
기존 `webpage-magician`의 **"주석 검토"** 탭 기능을 모두 옮겼고, 데이터가 사라지지 않도록 저장 구조를 새로 만들었습니다.

## 기능

### 기존 "주석 검토" 탭 기능 (모두 포함)
| 기능 | 내용 |
|---|---|
| 제품 목록 | 제품 추가, 검색, 새로고침, 삭제, 차수별 상태 배지(미작성 / N장·M주석 / ✅ 완료), 전체 완료 제품 흐리게 표시 |
| 차수 | 기본 1·2차, `+ 차수`로 3·4차… 추가, 차수 탭 전환, 차수별 편집 버튼 |
| 업로드 | 이미지 여러 장, HTML 파일(안의 `<img>`를 이미지 페이지로 가져오기), 소스코드(.css .js .ts .jsx .tsx .vue .txt 등), 이미지 URL 추가(CDN 프록시 URL 자동 해제), **현재 페이지 교체** |
| 주석 | 드래그로 박스 지정, 5가지 색상, 번호 배지, 코멘트 입력, 삭제, 박스↔목록 hover 연동·클릭 이동 |
| 페이지 | ◀ ▶ 페이지 이동, 썸네일 스트립 |
| 차수 완료 | 목록·편집 화면에서 완료 처리 / 완료 취소 |
| 외부 공유 | 제품 단위 공유 링크 → **읽기 전용** 뷰어(차수 탭, ✅ 확인 완료 배지, 페이지·썸네일, 주석 목록) |

### 추가·개선된 기능
- **매일 오후 9시(한국 시간) 자동 백업**: 사용자가 아무것도 하지 않아도 서버가 백업합니다. 21시에 서버가 꺼져 있었다면 그날 서버가 다시 켜지는 즉시 백업합니다. 최근 30개를 보관하고, [백업 관리]에서 지금 백업 / 다운로드(.tar.gz) / 복원을 할 수 있습니다. 복원하기 직전의 상태도 자동으로 백업됩니다.
- **"Failed to fetch" 후 데이터가 사라지던 문제 해결** (아래 "데이터 보호 구조" 참고)
- **오류가 나면 반드시 알림**: 깨진 이미지, 확장자와 실제 형식이 다른 파일, HEIC(아이폰 사진), 너무 큰 파일, 빈 파일, 업로드·저장 중 네트워크 오류, 다른 사람이 먼저 저장한 경우(충돌), 페이지가 갑자기 줄어드는 저장, 저장하지 않고 나가기 등 모든 경우에 이유와 대처 방법을 팝업으로 안내합니다.
- **디자인 개선**: 밝은 화면, Pretendard 글꼴, 카드형 제품 목록, 2단 툴바, 읽기 쉬운 주석 카드, 모바일 대응 뷰어
- 그 밖의 기능: 핀(지점) 주석, 주석 ‘해결’ 체크, 주석 드래그 이동, 페이지 삭제, 썸네일 드래그로 순서 변경, 드래그&드롭 / Ctrl+V 이미지 붙여넣기, 텍스트 직접 입력, 차수별 **버전 기록**(직전 50개 저장본 되돌리기), 완료된 차수 잠금, 휴지통(삭제 제품 복원), 공유 링크 재발급, 단축키(B 박스 · P 핀 · Delete 삭제 · Ctrl+S 저장 · ←/→ 페이지), 선택 비밀번호 보호(`APP_PASSWORD`), 기존 webpage-magician 데이터 가져오기

## 데이터 보호 구조 (데이터 소실 원인과 대책)

기존 시스템에서 데이터가 통째로 사라진 원인은 다음과 같습니다.

1. 모든 이미지를 base64로 `products.json` **한 파일**에 넣고, 저장할 때마다 그 파일 전체를 다시 썼습니다. 파일이 커지면 요청이 실패하거나(“Failed to fetch”) 서버 메모리가 부족해지고, 쓰는 도중 중단되면 파일이 깨졌습니다.
2. 파일이 깨지면 서버가 **빈 데이터로 시작**했고, 다음 저장이 그 빈 상태로 원본을 덮어썼습니다.
3. 데이터 폴더 기본값이 앱 폴더라서 Railway에서 **재배포하면 초기화**됐습니다.
4. 차수를 불러오지 못해도 화면에 이전 내용이 남아 있어, 잘못된 차수에 덮어쓸 수 있었습니다.

이번 구현의 대책은 다음과 같습니다.

| 대책 | 설명 |
|---|---|
| 파일 분리 저장 | 이미지는 **올리는 즉시 한 장씩** 서버에 저장합니다(내용 해시 이름, 수정 불가). 저장 버튼은 작은 메타데이터만 보내므로 요청이 커서 실패하지 않습니다. |
| 업로드 이중 검증 | 브라우저에서 실제로 열어 보고(디코딩), 서버에서 파일 앞부분(매직 바이트)을 다시 확인합니다. 문제가 있는 파일은 **그 파일만** 제외하고 이유를 알려줍니다. |
| 원자적 저장 | 임시 파일 → fsync → rename 순서로 저장하고 직전 파일을 `.bak`으로 보관합니다. 디스크 저장이 성공했을 때만 메모리에 반영합니다. |
| 자동 복구 / 안전 모드 | 시작할 때 `db.json`이 깨져 있으면 `.bak` → 최신 백업 순서로 자동 복구합니다. 복구할 수 없으면 **쓰기를 차단**합니다. 빈 데이터로 덮어쓰지 않습니다. |
| 저장 전 서버 검증 | 서버에 없는 파일을 가리키는 페이지가 있으면 저장을 거부합니다. 페이지 수가 줄어드는 저장은 한 번 더 확인합니다. |
| 충돌 감지 | 차수마다 revision 번호를 두어, 다른 창·사람이 먼저 저장했으면 덮어쓰지 않고 선택하게 합니다. |
| 브라우저 임시 보관 | 저장하지 않은 작업은 브라우저에 자동으로 임시 보관됩니다. 저장 실패, 창 닫힘, 새로고침 뒤에도 다시 열면 복구할 수 있습니다. |
| 버전 기록·휴지통·백업 | 실수로 지우거나 덮어써도 되돌릴 수 있습니다. |

## 실행

```bash
npm start
```

Node.js 18.17 이상이 필요하며, 외부 패키지 의존성은 없습니다. 기본 주소는 http://localhost:8080 입니다.

```bash
npm test
```

### 환경 변수
| 변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | 8080 | 포트 |
| `DATA_DIR` | Railway 볼륨 경로, 없으면 `./data` | 데이터·백업 저장 위치 |
| `BACKUP_TIME` | `21:00` | 매일 자동 백업 시각 |
| `TZ` | `Asia/Seoul` | 백업 시각 기준 시간대 |
| `BACKUP_KEEP` | 30 | 보관할 자동 백업 개수 |
| `MAX_UPLOAD_MB` | 30 | 파일당 최대 업로드 크기 |
| `APP_PASSWORD` | (없음) | 설정하면 편집 화면에 비밀번호가 필요합니다. 공유 링크는 비밀번호 없이 열립니다. |

## Railway 배포 (중요: Volume 필수)

1. 이 저장소로 Railway 서비스를 만듭니다. `railway.json`이 포함되어 있습니다.
2. **서비스 → Settings → Volumes → New Volume**에서 Mount path를 `/data`로 지정합니다.
   - 볼륨을 연결하면 `RAILWAY_VOLUME_MOUNT_PATH`가 자동으로 잡히고, 데이터·백업이 그 위치에 저장됩니다.
   - **볼륨이 없으면 재배포할 때마다 모든 데이터가 사라집니다.** 이 경우 앱 상단에 경고 배너가 표시됩니다.
3. (선택) `APP_PASSWORD`를 설정합니다.
4. 기존 webpage-magician 데이터 옮기기: 앱 오른쪽 위 **백업 관리 → 기존 시스템 데이터 가져오기**에 기존 서버 주소(예: `https://webpage-magician-production.up.railway.app`)를 넣고 [서버에서 가져오기]를 누릅니다. 가져오기 전에 자동으로 백업이 만들어지고, 이미 가져온 제품은 건너뜁니다.

> 백업은 같은 볼륨에 저장됩니다. 볼륨 자체의 장애에 대비하려면 가끔 [백업 관리 → 다운로드]로 PC에도 받아 두세요.

## 폴더 구조
```
server.js            HTTP 서버 / API
lib/store.js         메타데이터 저장소 (원자적 저장, 자동 복구, 안전 모드, 버전 기록)
lib/files.js         업로드 파일 저장·형식 검증
lib/backup.js        매일 자동 백업, 복원, 다운로드
lib/legacy.js        기존 webpage-magician 데이터 가져오기
public/              화면 (index.html 편집기, viewer.html 읽기 전용 공유 뷰어)
test/                서버 테스트 (node --test)
```
